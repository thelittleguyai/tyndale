# Golden Eval Examples

Expert-labeled examples used to evaluate Tyndale's intelligence layer.

## Structure

- `per_skill/` — examples organized by Skill
- `per_subagent/` — examples organized by subagent
- `voice_and_safety/` — examples for voice tier compliance and refusals

## File naming

Use the pattern `<category>_<sequence>.json`:
- `per_skill/bill_error_detection/bundling_001.json`
- `voice_and_safety/tier_b_legal/nsa_violations_002.json`

Each file contains ONE example matching `schema.json`. See
`per_skill/bill_error_detection/EXAMPLE.json` for a complete template.

## Authoring

- Brock authors most examples
- Contracted attorney authors complex legal-interpretation examples
- Billing advocate authors complex bill-detection examples
- Synthetic adversarial cases (author `synthetic_opus47`) are generated by the runner in
  `../synthetic/` and slot into the same schema/runner.

## Target counts at V1

~400 total examples across all categories. Specific targets:
- `per_skill`: ~50 per Skill (8 Skills = ~400 examples)
- `per_subagent`: ~30 per subagent (6 subagents = ~180 examples)
- `voice_and_safety`: ~50 examples total

(These overlap — a `bill_error_detection` example also tests `bill_detective`. So the actual
unique example count is ~400–600.)

### V1-Lite note

**V1-Lite ships with a subset of these target counts — roughly ~200–400 examples vs. the full
~400–600 target.** The feedback loop (Phase 4) grows the suite from real production cases
post-launch (every caught mistake becomes a case). Prioritize the V1-Lite-active Skills/subagents
(Bill Error Detection, Cost Estimation, Coverage Connection, Negotiation diagnostic; Lead Planner
V1-Lite, Bill Detective, Math Person) and the voice/refusal categories; the deferred Full-V1
Skills/subagents (Document Generation, Charity Care; Legal Researcher, Strategist, Code Validator)
have empty placeholder directories until Full V1.

## Quality criteria

Every golden example must:
- Have a clear, testable `expected_output_traits` section
- Have author-provided `expert_reasoning` explaining why the answer is correct
- Be reviewed by a second author before merge

## How these get used

Braintrust evals run these against Tyndale's intelligence layer every PR. Regression below
baseline blocks merge.

The LLM judge (Opus 4.7) scores outputs against the `expected_output_traits`. Cohen's κ ≥ 0.6
between judge and human reviewer is required for the judge to be considered calibrated.
