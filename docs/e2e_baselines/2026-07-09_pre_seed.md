## Stage timings (for Phase-3 capacity sizing)

Across the 8 scenarios that ran a full audit:

- **audit_s** (the dominant cost): min 127.9 · **p50 ≈ 163** · **p95 ≈ 285** · max 284.5
- **extract_s**: 18–49 (median ≈ 33)
- **upload_s**: 4.5–13.1

An audit is a **2–5 minute** synchronous-ish agent run. Phase 3 should size the runtime container
and uvicorn `--workers` off the p95 audit duration + expected concurrency (one in-flight audit per
worker for minutes at a time).

## Failure triage

**Harness-assertion corrections (fixed this phase — the Phase-1 invariant held):**
- `blank_pages`, `unreadable_document` → **`not_a_bill`**, not `extraction_failed`. On **real** Azure
  DI a blank/garbage PDF still yields a trivial bit of text, so it reads as "readable but not a
  bill" rather than "unreadable." Both are honest **no-encounter** terminals — which is the whole
  point of Phase 1 (never a 0-item encounter). Assertion loosened to accept either. ✅ now pass.

**Regression introduced by Phase 1 (`4ae4fd1`) — recommend fixing before the seed:**
- `collections_only` → **`not_a_bill`** (expected `audit_incomplete`; case `5e8b2b97`). The new
  `not_a_bill` branch fires for *any* readable doc outside the bill/EOB family — so it now also
  catches **recognized medical documents** (collections notice, denial letter, insurance card,
  plan summary) that should proceed to the audit's `needs_documents` flow, not dead-end.
  **Recommended fix:** fire `not_a_bill` only when every readable doc is `unclassified` (genuinely
  non-medical); let recognized-but-non-bill medical docs fall through. Small, contained change in
  `orchestrator.extract_line_items`. *(Not hot-fixed here per the Phase-2 boundary — flagged for a
  Phase-1 follow-up decision.)*

**Pre-existing product bugs (NOT touched by Phase 1 — for prioritization):**
- **6× `500` on `GET /v1/audit/{id}`** (`balance_billing_mismatch`, `duplicate_cpt_line`,
  `eob_only_no_bill`, `preventive_cost_shared`, `unbundled_panel`, `upcoded_em_level`). Each ran a
  full audit to a terminal state, then the result **fetch** 500'd. `GET /audit/{id}` →
  `orchestrator._assemble_result`, which Phase 1 did not modify — so this predates this deploy
  (candidate origin: the `plan_types v2` deploy `cd8a011`, or older). **Needs the dev traceback**
  (no local Azure log access from this session). The 2 audits that fetched cleanly
  (`encounter_mismatch_phantom`, `msn_medicare`) suggest a data-shape-dependent failure in result
  assembly. **Highest-severity finding.**
- `clean_bill_matching_eob` → 1 finding on a clean bill (expected 0; case `9a3dd104`). Audit/eval
  precision — a false-positive finding.
- `deductible_misapplied` → `audit_incomplete` (expected `audit_complete`; case `bb392cba`). The
  audit stopped short of a complete result.

## What this baseline establishes

- Phase 1's **magic-byte upload gate works on dev** (`not_a_bill_txt` → 422).
- Phase 1's **no-0-item-encounter invariant holds** (`blank_pages`, `unreadable_document` degrade
  to honest terminals, never an encounter).
- Two audit scenarios pass end-to-end (`encounter_mismatch_phantom`, `msn_medicare`).
- **Open before the seed:** the `GET /audit/{id}` 500 (6 scenarios) and the `not_a_bill`
  over-capture regression are the two things to resolve so the post-seed diff is meaningful.
